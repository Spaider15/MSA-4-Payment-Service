# Задание 5. Тесты

Окружение поднимаем через Testcontainers (PostgreSQL, Redis, Camunda), внешние сервисы (AML, GeoRisk, банк) мокаем WireMock. Таймеры в тестах укорачиваем через конфиг.

| Название | Тип | Компоненты | Предусловия |
|---|---|---|---|
| Успешный платеж | E2E | Orchestrator, Payment Service, FraudCheck Service, Notification Service, PostgreSQL, Redis | У клиента хватает денег, все проверки возвращают разрешение. Ожидаем статус COMPLETED, деньги у контрагента, клиент уведомлен, время < 5 сек |
| Запрет антифрода | E2E | Orchestrator, Payment Service, FraudCheck Service, Notification Service | Деньги списаны, антифрод возвращает запрет. Ожидаем возврат денег, статус DECLINED, уведомление в безопасность и клиенту |
| Ручная проверка - разрешено | E2E | Orchestrator, Payment Service, FraudCheck Service | Антифрод возвращает "ручная проверка", оператор разрешает. Платеж проводится |
| Ручная проверка - запрещено | E2E | Orchestrator, Payment Service, FraudCheck Service, Notification Service | Антифрод возвращает "ручная проверка", оператор запрещает. Деньги возвращаются, статус DECLINED |
| Ручная проверка - истекло 20 минут | Интеграционный | Orchestrator, FraudCheck Service, Payment Service | Оператор не отвечает, таймер укорочен. Платеж считается разрешенным и проводится |
| Cut-off автоматических проверок | Интеграционный | Orchestrator, FraudCheck Service, WireMock (AML) | AML не отвечает дольше cut-off. Платеж проводится по умолчанию |
| Проверки идут параллельно | Интеграционный | FraudCheck Service, WireMock (AML, GeoRisk) | Каждый провайдер отвечает за 1 сек. Общее время проверки ~1 сек, а не 3 |
| Кэширование результатов проверок | Интеграционный | FraudCheck Service, Redis, WireMock (AML) | Два платежа одного клиента подряд. Во внешний AML уходит только один запрос |
| Недостаточно средств | Интеграционный | Orchestrator, Payment Service | Баланс меньше суммы. Статус FAILED, антифрод не вызывается, возврат не нужен |
| Отказ перевода контрагенту | E2E | Orchestrator, Payment Service, WireMock (банк), Notification Service | Проверки пройдены, банк окончательно отклоняет перевод. Деньги возвращаются клиенту, статус FAILED |
| Повтор перевода при временной ошибке | Интеграционный | Orchestrator, Payment Service, WireMock (банк) | Банк 2 раза отвечает 503, потом успех. Перевод выполнен один раз |
| Повтор возврата при временной ошибке | Интеграционный | Orchestrator, Payment Service | Первые попытки возврата падают. Возврат в итоге проходит ровно один раз |
| Идемпотентность списания и возврата | Интеграционный | Payment Service, PostgreSQL | Повторная команда с тем же paymentId. Повторного списания/возврата нет |
| Повторный запрос по тому же заказу | Интеграционный | Orchestrator, Payment Service | Платеж по orderId уже создан. Новый процесс не стартует, деньги не списываются второй раз |
| Отмена клиентом во время ручной проверки | E2E | Orchestrator, Payment Service, FraudCheck Service | Платеж в MANUAL_REVIEW, клиент отменяет. Задача оператора отозвана, деньги возвращены, статус CANCELLED |
| Отмена клиентом после перевода | Интеграционный | Orchestrator, Payment Service | Платеж уже TRANSFERRED. Отмена не принимается, статус не меняется |
| Перезапуск оркестратора | E2E | Orchestrator, Payment Service, FraudCheck Service, PostgreSQL | Платеж ждет ручную проверку, контейнер оркестратора перезапускается. Процесс продолжается с того же шага |
| Недоступен Notification Service после перевода | Интеграционный | Orchestrator, Notification Service | Перевод выполнен, Notification Service лежит. Платеж не откатывается, уведомление отправляется после восстановления |
| Нет зависших денег | E2E | Orchestrator, Payment Service, WireMock (банк), PostgreSQL | Прогоняем пачку платежей с разными исходами. В конце баланс транзитного счета = 0, нет платежей в нефинальных статусах |
